## 1. Why this leg exists

Leg 1's end-to-end run against a live 970k-node graph produced two findings that its unit
suite could not: the enumerating accessors are unusably slow, and the dataflow half of the
graph is not reachable through the SDK at all.

Neither is a defect in leg 1's additions. Both are properties of accessors that predate it,
exposed the moment a real application was pointed at them. This leg fixes the first and
delivers the second.

**The governing principle, inherited from the parent spec:** *the front end does the graph
work*. Leg 1 applied that to correctness — a caller should not hand-roll a traversal because
it cannot tell a missing edge from a true negative. Leg 1.5 applies the same rule to volume:
a caller should not receive a 364,752-edge call graph because it asked a question about one
function.

---

## 2. Evidence

Measured against `odoo-slim-19.0.0` (2,364 Python files) projected by `codeanalyzer-python`
1.4.0 — 970,616 nodes, ~7.7M relationships.

| Accessor | Time | Result |
| --- | --- | --- |
| `get_callables_overview()` | 0.6s | 15,549 |
| `get_artifacts()` | 0.8s | 10,196 |
| `get_dependencies()` | 0.0s | 97 |
| **`get_classes()`** | **347.6s** | 1,642 |
| **`get_symbol_table()`** | **381.7s** | 1,626 |
| **`get_call_graph_json()`** | **422s** | — |

**The cause is round-trip count, not database load.** Instrumenting `get_symbol_table()`:

```
1,626 modules → 73,669 round trips → 45.3 queries per module → 4.9ms each → 363s
```

Neo4j answers each query in 5ms. We ask it seventy-three thousand times, because
`_module_full` fans out per module, `_class_full` fans out per class (methods, attributes,
inner classes), and `_callable_full` fans out again per callable.

`get_callables_overview()` proves the point by contrast: same graph, one query, 15,549 rows,
0.6s. The projection accessors were already right.

**This is why distributed fetch is the wrong first lever.** Sharding parallelises server work;
the bottleneck here is the count of sequential round trips. Fix the fan-out and the same
result is a handful of queries — then parallelise, if a 1.2M-node graph still warrants it.

### 2.1 The dataflow graph is present and unreachable

The projection carries a complete system dependence graph that no accessor exposes:

| Relationship | Edges |
| --- | --- |
| `PY_DDG` | 5,134,655 |
| `PY_SUMMARY` | 453,398 |
| `PY_CFG_NEXT` | 247,906 |
| `PY_PARAM_IN` | 229,035 |
| `PY_CDG` | 139,065 |
| `PY_PARAM_OUT` | 133,267 |

Slicing and reachability are the queries this data exists to answer, and they are exactly the
queries a variable-length Cypher path expresses in milliseconds and a Python-side traversal
cannot finish.

## 3. Locked decisions

| | Decision | Rationale |
| --- | --- | --- |
| **E1** | **Collapse the fan-out before anything else.** One query per *collection*, not per *node*, using Cypher `collect()` to return nested structures. | 73,669 → single digits. No new infrastructure, no API change, and it is a precondition for judging whether any further optimisation is warranted. |
| **E2** | **A slice is a set; a path is a sequence.** They are separate accessors and neither is derived from the other. | A backward cone of 10k nodes can contain millions of distinct paths. Returning paths from a slice call is unbounded by construction; returning a set from a path call cannot justify itself. |
| **E3** | **Traversal executes in the database.** Slicing and reachability compile to variable-length Cypher; the SDK never materialises the SDG in Python. | 5.1M `PY_DDG` edges. This is the case Neo4j exists for, and it is the parent spec's "the front end does the graph work" applied to volume. |
| **E4** | **Identifiers by default; payloads on request.** Slice and path accessors return `can://` ids. Hydration is a separate bulk call. | Returning source text for a 10k-node slice recreates the flooding this leg exists to remove. The caller decides what it can afford to read. |
| **E5** | **Every unbounded accessor grows a bound.** Depth, result caps, and scoping arguments — with truncation reported in the result, never silent. | An agent cannot ask a follow-up question. A silently truncated result is the ambiguous-empty defect wearing a different hat. |
| **E6** | **No signature moves.** Every existing accessor keeps its name, parameters and return type; bounds arrive as defaulted keywords, new capability as new accessors. | Leg 1's D4, unchanged. Defaulted keywords are an accepted widening in this repo. |

## 4. Part A — bounded enumeration

### 4.1 Collapse the fan-out (E1)

`_module_full`, `_class_full` and `_callable_full` each issue one query per child collection.
Replace with one query per accessor that returns the whole shape:

```cypher
MATCH (:PyApplication {name: $app})-[:PY_HAS_MODULE]->(m:PyModule)
OPTIONAL MATCH (m)-[:PY_DECLARES]->(c:PyClass)
OPTIONAL MATCH (c)-[:PY_HAS_METHOD]->(meth:PyCallable)
RETURN m, collect(DISTINCT {class: c, methods: collect(DISTINCT meth)}) AS classes
```

Reconstruction moves from "query per node" to "walk the returned structure". The public
return types do not change — `Dict[str, PyModule]` stays `Dict[str, PyModule]`.

**Target: `get_symbol_table()` and `get_classes()` under 10 seconds on this graph**, from 382s
and 348s. The e2e suite's existing 900s ceilings tighten to match, so a regression is caught.

### 4.2 Scoping arguments (E5)

Whole-application enumeration should be the exception, not the default shape:

```python
def get_symbol_table(self, *, paths: Sequence[str] | None = None) -> Dict[str, PyModule]: ...
def get_classes(self, *, module: str | None = None) -> Dict[str, PyClass]: ...
def get_call_graph(self, *, roots: Sequence[str] | None = None,
                   depth: int | None = None) -> nx.DiGraph: ...
```

All defaulted, so existing calls are unaffected. `get_call_graph(roots=…, depth=…)` is the
one that matters for agents: 364,752 edges is not an answer to a question about one function.

### 4.3 `get_call_graph_json` (recorded defect)

422s because `get_application_view()` builds the entire symbol table and then discards it by
raising. That is waste, not enumeration cost, and E1 removes most of it; the discarded-work
path should go regardless.

## 5. Part B — dataflow access

### 5.1 Per-callable graphs

Naturally bounded — one callable's edges, no traversal:

```python
def get_cfg(self, callable_signature: str) -> List[CfgEdge]: ...
def get_cdg(self, callable_signature: str) -> List[CdgEdge]: ...
def get_ddg(self, callable_signature: str) -> List[DdgEdge]: ...
```

`DdgEdge` carries `var` and `prov`, so a caller can filter syntactic (`ssa`, `reaching-defs`)
from alias-aware (`points-to`) evidence without a second call.

### 5.2 Slices — sets (E2)

```python
class Slice(BaseModel):
    nodes: set[str]                  # can:// ids
    root: str
    truncated: bool                  # a cap was hit — never silent (E5)
    diagnostics: list[Diagnostic]

def slice_backward(self, node_id: str, *, depth: int | None = None,
                   prov: Sequence[str] | None = None,
                   max_nodes: int = 10_000) -> Slice: ...
def slice_forward(self, node_id: str, ...) -> Slice: ...
```

Reverse (or forward) reachability over `PY_DDG | PY_CDG | PY_PARAM_IN | PY_PARAM_OUT |
PY_SUMMARY`, executed as one variable-length Cypher match. `prov` filters the edge evidence —
an L3-only slice is a strict subset of an L4 one, and a caller arguing soundness needs to say
which it used.

### 5.3 Paths — sequences (E2)

```python
class PathEdge(BaseModel):
    src: str; dst: str
    kind: str                        # which relationship justified this hop
    var: str | None
    prov: list[str]

class FlowPath(BaseModel):
    edges: list[PathEdge]            # ordered, src → dst
    weakest: PathEdge                # least certain edge on the path

def paths_between(self, src: str, dst: str, *, max_paths: int = 10,
                  max_depth: int | None = None) -> List[FlowPath]: ...
def flows_to(self, src: str, dst: str) -> bool: ...
def reachable_by(self, node_id: str, *, depth: int | None = None) -> Slice: ...
```

`paths_between` is what an agent needs to *argue* a flow: ordered hops, each carrying the
edge that justifies it. `max_paths` is mandatory-by-default because path count is exponential
in cone size.

`flows_to` is the cheap boolean — `EXISTS` in Cypher, no path materialised — for the common
case of checking rather than explaining.

### 5.4 Hydration (E4)

```python
def describe(self, node_ids: Sequence[str]) -> List[LocateResult]: ...
```

One bulk call turning ids into `LocateResult`s — source slice, enclosing callable, span —
reusing leg 1's addressing layer rather than inventing a second shape. A caller slices, reads
the count, decides how much it can afford, then hydrates that subset.

## 6. Staging

| Step | Content | Gate |
| --- | --- | --- |
| 1 | Collapse the fan-out in `_module_full` / `_class_full` / `_callable_full` (E1) | `get_symbol_table` and `get_classes` < 10s on the odoo graph; existing tests unmodified |
| 2 | Scoping keywords on the enumerating accessors (E5); drop `get_application_view`'s discarded work | existing calls unaffected; `get_call_graph(roots=…)` bounded |
| 3 | Per-callable `get_cfg` / `get_cdg` / `get_ddg` | both backends, parity tested |
| 4 | `slice_backward` / `slice_forward` / `reachable_by` (E2, E3, E5) | slice over a known fixture equals the hand-computed node set exactly |
| 5 | `paths_between` / `flows_to` / `describe` (E2, E4) | a known flow's path matches hop for hop, including `var` and `prov` |

Steps 1–2 are pure performance and touch no public shape. Steps 3–5 are additive. The split
matters: step 1 can merge on its own value, and every later step is measured against a graph
that answers in seconds rather than minutes.

**Every step is verified against the live graph, not fixtures.** Leg 1 shipped six accessors
broken on every real graph through 159 green unit tests, because hand-written fixtures encode
the author's model of the data and can only confirm it. The e2e suite from leg 1 is the
template.

## 7. Definition of done

- `get_symbol_table()` and `get_classes()` complete in under 10 seconds on the odoo graph;
  round-trip count for `get_symbol_table` is single-digit, asserted by an instrumented test.
- `get_call_graph(roots=…, depth=…)` returns a bounded subgraph; the unbounded form still works.
- `get_cfg` / `get_cdg` / `get_ddg` return a real callable's edges on both backends, in parity.
- A backward slice over a fixture equals the hand-computed node set exactly.
- A known source→sink flow returns a path whose hops match edge for edge, with `var` and `prov`.
- Every capped accessor reports `truncated` when it truncates; no cap is silent.
- Every accessor above is exercised against the live graph in the e2e suite, not only fixtures.

## 8. Out of scope

**Taint.** This leg delivers the graph queries taint is built *from* — slicing, reachability,
paths — not a policy engine. Sources, sinks and sanitizers remain leg 4, and remain the
caller's to supply.

**Distributed or sharded fetch.** Deliberately deferred until E1 lands: the current bottleneck
is 73,669 sequential round trips, and parallelising that before collapsing it would optimise
the wrong quantity. Revisit with measurements from a 1.2M-node graph once step 1 is in.

**Cross-language rollout.** Java and TypeScript are legs 2 and 3. The Cypher here is
prefix-parameterised like leg 1's, so it ports, but proving that is not this leg's job.

**The three upstream analyzer issues** surfaced by leg 1's live run — zero entrypoints detected
in Odoo, half-dedented nested-callable source, and external→app `PY_CALLS` edges invisible to
module scoping — belong to `codeanalyzer-python`.
