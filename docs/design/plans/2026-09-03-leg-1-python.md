# CLDK 2.0 Leg 1 — Python Implementation Plan

> **Note on authorship:** per `CLAUDE.md`, the maintainer writes the implementation. Code blocks
> below are specifications of intent — exact enough to be unambiguous about names, types and
> behaviour — not code to paste. Test blocks are meant to be written as-is, since the tests are
> the contract.

**Goal:** Bring the Python facade onto `codeanalyzer-python` 1.4.0 behind an unchanged public API,
add the addressing / body / artifact / entrypoint surface, make version mismatch loud, and delete C.

**Architecture:** A generic `AnalysisBackend` ABC defines the query shape; `PythonAnalysisBackend`
parameterises it with Python's own models (no shared declaration models). The Neo4j backend moves
from the stale `PyCallSite` / `PY_HAS_CALLSITE` vocabulary to 1.4.0's `PyBodyNode` /
`PY_HAS_BODY_NODE`, and probes the attached graph on connect so a generation mismatch raises
instead of returning zero rows.

**Tech Stack:** Python 3.11+, pydantic v2, neo4j Python driver, pytest, `codeanalyzer-python` 1.4.0.

**Spec:** `docs/design/specs/2026-09-03-agent-facing-query-facade.md`

**Tracking:** codellm-devkit/.github#55 (epic). Closes #315, #316, #317, #301.

## Global Constraints

- **Public API signatures do not move.** Every existing accessor on `PythonAnalysis` keeps its
  name, parameters and return type. This is D4 and it is enforced per task: the existing
  `tests/analysis/python/` suite must pass unmodified after every task.
- **Python floor:** `>=3.11`. **pydantic:** `>=2.10.6,<3`.
- **Analyzer pin:** `codeanalyzer-python==1.4.0`, exact.
- **Neo4j access is read-only.** No `CREATE`, `MERGE`, `SET`, or `DELETE` in any Cypher this leg
  adds. Derivation and materialisation are out of scope for 2.0.
- **Absence is never `null`.** A fact is present or absent; the one sanctioned null is a body
  node's `callee` before L2 resolution.
- **No new dependencies.** This leg removes four and adds none.
- **Branch per task group:** `feat/issue-NNN-<short-title>`, one PR per task, per `CLAUDE.md` Rule 3.

## Task 3: `graph_schema_mismatch` — make version drift loud

This precedes the vocabulary migration deliberately: it is the check that would have caught the
drift, and writing it first means Task 4 has a test that fails for the right reason.

**Files:**
- Modify: `cldk/utils/exceptions/` — add `GraphSchemaMismatch`
- Create: `cldk/analysis/commons/results.py` — `Diagnostic`
- Modify: `cldk/analysis/python/neo4j/neo4j_backend.py`
- Test: `tests/analysis/python/test_schema_probe.py`

**Interfaces:**
- Produces:
  ```python
  class Diagnostic(BaseModel):
      code: Literal["no_match", "ambiguous", "unknown_callable", "unknown_param",
                    "did_you_mean", "level_too_low", "module_scope",
                    "file_not_in_graph", "unresolved_dispatch", "graph_schema_mismatch"]
      message: str
      suggestions: list[str] = []

  class GraphSchemaMismatch(RuntimeError):
      expected: set[str]; found: set[str]; missing: set[str]
  ```
  and `PyNeo4jBackend._probe_schema()`, called once from `__init__`.

- [ ] **Step 1: Write the failing test**

```python
# tests/analysis/python/test_schema_probe.py
import pytest
from cldk.utils.exceptions import GraphSchemaMismatch
from cldk.analysis.python.neo4j.neo4j_backend import PyNeo4jBackend

REQUIRED = {"PY_HAS_MODULE", "PY_HAS_METHOD", "PY_HAS_BODY_NODE", "PY_CALLS"}

def test_probe_raises_on_v1_graph(fake_driver):
    """A graph built by codeanalyzer-python 0.3.x has PY_HAS_CALLSITE, not PY_HAS_BODY_NODE."""
    fake_driver.rel_types = {"PY_HAS_MODULE", "PY_HAS_METHOD", "PY_HAS_CALLSITE", "PY_CALLS"}
    with pytest.raises(GraphSchemaMismatch) as e:
        PyNeo4jBackend(fake_driver, application_name="app")
    assert "PY_HAS_BODY_NODE" in e.value.missing
    assert "PY_HAS_CALLSITE" in str(e.value)      # names what it found, not just what it wanted

def test_probe_passes_on_v2_graph(fake_driver):
    fake_driver.rel_types = REQUIRED | {"PY_DDG", "PY_PARAM_IN"}
    PyNeo4jBackend(fake_driver, application_name="app")   # no raise

def test_probe_raises_on_empty_graph(fake_driver):
    """An asset-only graph must not look like an application with no code."""
    fake_driver.rel_types = set()
    with pytest.raises(GraphSchemaMismatch):
        PyNeo4jBackend(fake_driver, application_name="app")
```

- [ ] **Step 2: Run it and watch it fail**

Run: `pytest tests/analysis/python/test_schema_probe.py -v`
Expected: FAIL — `ImportError: cannot import name 'GraphSchemaMismatch'`.

- [ ] **Step 3: Add the two test fixtures these tests need**

`fake_driver` and `query_counter` do not exist yet; add them to

- [ ] **Step 4: Implement the probe**

`_probe_schema()` runs `CALL db.relationshipTypes()` once at construction, compares against

types, the types actually present, and the analyzer generation each implies — a graph carrying

One round trip per connection, not per query.

Expected: PASS.

```bash
A graph built by a different analyzer generation returned zero rows with no
```

**Interfaces:**

  ```python
  def locate(self, path: str, line: int, col: int | None = None) -> LocateResult: ...

  ```

```python
def test_locate_inside_callable(py):
    r = py.locate("src/app.py", 19)
    assert r.callable.signature == "src.app.Store.key"
    assert r.source.startswith("    def key(")     # the callable's text, not the file's
    assert r.diagnostics == []

    """A module top-level statement is a real position, not an absence."""
    r = py.locate("src/app.py", 1)
    assert r.callable is None
    assert r.module.path == "src/app.py"

    assert r.callable is None
    assert [d.code for d in r.diagnostics] == ["module_scope"]

    r = py.locate("test/conftest.py", 3)
    assert [d.code for d in r.diagnostics] == ["file_not_in_graph"]
```

```bash
LocateResult keeps those four outcomes apart and carries the source slice, so
```
