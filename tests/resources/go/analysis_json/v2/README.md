The historical notes below describe earlier fixture generations and are superseded by this section.

The Go analysis fixture is a single schema-v2 output committed one directory up, at
`tests/resources/go/analysis.json`, generated by **codeanalyzer-go** (`cango`) on the application in
`tests/resources/go/litestream.zip` (the [litestream](https://github.com/benbjohnson/litestream) Go
project). It is the real `can://go/litestream` corpus: 55 modules, 959 call-graph edges,
`max_level: 2`.

    # unzip litestream.zip -> litestream/ (carries go.mod at its root)
    cango -i litestream --app-name litestream -a 2 -o <dir> --cache-dir <dir> --skip-tests

That is the command `GoCodeanalyzer._argv` builds (`cldk/analysis/go/codeanalyzer/codeanalyzer.py`),
with `--app-name` defaulting to the input directory's basename (`litestream`). `-a` is capped at
**2**: cango has no L3/L4, so this corpus is a single level-2 file — there is no `a1`/`a2`/`a3`/`a4`
per-level split, unlike the TypeScript and Java resource trees, because cango's L1 output is a strict
subset of its L2 output and nothing in the suite needs the shallower generation.

**No version pin yet.** codeanalyzer-go has not cut a release, so there is no wheel to pin and no
`analyzer.version` to assert against (the committed JSON stamps `"version": "0.1.0"`, a dev build).
The binary is resolved at run time from `$CODEANALYZER_GO_BIN` (a locally built `cango`) or, once it
ships, the `codeanalyzer-go` PyPI wheel. `tests/analysis/go/test_go_e2e.py` unzips `litestream.zip`
and runs whichever binary it finds against it, skipping cleanly when neither is present. When the
release lands and the pin is added, regenerate `analysis.json` with the pinned binary and record its
version here.

**Schema v2, no `--analysis-schema` flag.** Earlier generations passed `--analysis-schema 2` to stop
cango emitting legacy v1; that flag was removed (`_argv` no longer sends it — the binary defaults to
v2). The committed JSON carries `"schema_version": "2.0.0"`; if a regeneration emits v1, the models
(an `extra="forbid"` mirror of canonical schema v2) refuse it rather than parse it.

**The application is committed as `tests/resources/go/litestream.zip`** so a regeneration runs on
exactly the source `analysis.json` describes. Regenerate the JSON whenever the zip changes.
